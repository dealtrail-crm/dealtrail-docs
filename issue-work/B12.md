## 배경

격리 메커니즘({{B11}})이 모든 엔티티에서 성립함을 두 계정으로 교차 검증하고, 반납된 계정을 새로 빌린 방문자가 이전 데이터를 어떤 경로로도 볼 수 없음을 확인하는 자동 테스트다. 엔티티별 격리 AC를 모두 여기서 한 시나리오로 검증한다.

- Epic: {{E1}}
- 선행: {{B11}}, Epic 2~6의 BE 이슈 전부 ({{B14}}~{{B34}})
- 설명 포인트: 작업 공간 격리 (검증). 핵심 이슈는 {{B11}}

## 유저 스토리

- `US-WS-3` 방문자로서, 내가 만든 데이터가 다른 방문자에게 보이지 않았으면 한다.

## 인수조건

- [ ] `AC-WS-26` 계정 두 개(테스트 계정 두 개 또는 테스트 계정 + 회원)로 각 엔티티에 대해 조회·수정·삭제·목록·집계를 교차 시도해 모두 "존재하지 않음"/영향 없음을 확인하는 자동 테스트
- [ ] `AC-WS-28` 반납(만료)된 테스트 계정을 새로 빌린 방문자는 이전 대여의 작업 공간·데이터를 식별자를 알아도 볼 수 없다 (정리 전·후 모두)
- [ ] `AC-LD-19` 전환 시 다른 작업 공간의 Account 식별자나 없는 식별자를 넣으면 "존재하지 않음"으로 거부되고 아무것도 생성되지 않는다
- [ ] `AC-ACC-08` Account·Contact가 `AC-COMMON-01~05`를 만족한다
- [ ] `AC-OP-22` 다른 작업 공간의 Opportunity에 단계 변경을 요청하면 "존재하지 않음"으로 거부된다
- [ ] `AC-AT-11` 다른 작업 공간의 엔티티를 대상으로 지정하는 Activity 생성은 "존재하지 않음"으로 거부된다
- [ ] `AC-DB-06` 집계는 요청한 작업 공간의 데이터만 포함한다. 다른 공간에 데이터가 많아도 수치에 영향이 없다
