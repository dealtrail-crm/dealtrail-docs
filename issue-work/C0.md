## 작업 내용

senior-backend가 모든 API 계약이 공유하는 횡단 규약을 `api/00-common.md`와 `api/openapi.yaml` 골격(서버 URL·공통 스키마·공통 에러 응답·보안 스킴)으로 작성한다. frontend가 소비자 관점에서 검토하고("이 규약으로 공통 유틸 {{F05}}·앱 셸 {{F02}}를 만들 수 있는가"), 사용자가 최종 승인한다. Epic별 계약({{C1}}~{{C7}})은 이 규약을 전제로 쓴다.

- Epic: 없음 (횡단 규약, Milestone만)
- 소비하는 FE 이슈: 모든 `[FE]` 이슈. 직접 소비: {{F02}}, {{F05}}
- 구현하는 BE 이슈: 모든 `[BE]` 이슈. 직접 구현: {{B01}}, {{B11}}

### 정할 것 (다루는 AC)

- `AC-COMMON-03` / `AC-COMMON-09`: "만료됨"과 "인증 필요" 거부 응답의 구분 방식 (상태 코드·사유 코드)
- `AC-COMMON-04`: 목록 페이지네이션 방식(offset·cursor), 페이지 크기 기본값·상한, 정렬 파라미터. 칸반(`AC-OP-21`)·대시보드(`AC-DB-01`)는 페이지네이션 예외
- `AC-COMMON-05`: 입력 검증 실패 응답 형식 — 어떤 필드가 왜 실패했는지 FE가 필드 옆에 표시할 수 있는 구조
- `AC-COMMON-06`: 금액은 KRW 정수. JSON 표현(number vs string)
- `AC-COMMON-12` `13`: 세션 보관 수단(쿠키 등), 식별자 형식, 유지 기간(테스트 계정 = 만료 시각, 회원 = 상한)
- `AC-COMMON-15`: 날짜·시각 형식(ISO 8601, Asia/Seoul 고정 또는 UTC + 오프셋), 날짜만 쓰는 필드(할 일 기한·예상 마감일) 표현
- `AC-WS-27`: 작업 공간·계정·엔티티 식별자 형식 (추측 불가, 순차 번호 금지)
- 업종 15개 값 표기 (`prd/00-overview.md` §4.1) — 코드 값과 표시명
- **방문자 IP 조건**: 테스트 계정 대여(`AC-WS-06`)와 회원가입(`AC-MB-06`) 요청은 **브라우저가 `/api`를 직접 호출**한다 (Next.js 서버 경유 시 방문자 IP를 잃음). 같은 도메인 경로 라우팅(Caddy `/api/*` → Spring)이라 CORS는 불필요하다. 계약에 "브라우저 직접 호출" 표시 규칙을 둔다. 근거: `HANDOFF.md` 1장 "인프라 구성"
