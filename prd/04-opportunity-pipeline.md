## 1. 목적

Opportunity는 금액·단계·예상 마감일을 가진 영업 건이다. 단계는 아무 값으로나 바꿀 수 있는 필드가 아니라 **허용된 전이만 가능한 상태 머신**이고, 바뀔 때마다 이력이 남는다. 파이프라인 칸반은 이 상태를 한눈에 보여 주는 기본 화면이며, 체험 시작 직후 방문자가 처음 보는 화면이다. 제품명(deal + trail)이 가리키는 "영업 건이 남긴 이력"이 이 기능에서 나온다.

## 2. 유저 스토리

- US-OP-1. 영업 담당자로서, 진행 중인 영업 건을 단계별 칸반으로 보고 싶다. 어느 단계에 무엇이 얼마나 몰려 있는지 파악하기 위해.
- US-OP-2. 영업 담당자로서, 카드를 다음 단계로 옮기고 싶다. 진행 상황을 바로 반영하기 위해.
- US-OP-3. 영업 담당자로서, 건너뛰거나 되돌리면 안 되는 단계 이동은 시스템이 막아 주길 원한다. 파이프라인 데이터가 뒤죽박죽 되지 않도록.
- US-OP-4. 영업 담당자로서, 어떤 건이 언제 어느 단계를 거쳤는지 이력을 보고 싶다. 정체된 건을 찾고 과정을 복기하기 위해.
- US-OP-5. 영업 담당자로서, 수주·실패로 마감한 건을 다시 열 수 없길 원한다. 집계 수치가 사후에 흔들리지 않도록.
- US-OP-6. 영업 담당자로서, Lead 전환 없이도 기존 거래처에 새 영업 건을 만들고 싶다. 재구매·추가 제안을 기록하기 위해.

## 3. 인수조건

### 3.1 Opportunity 기본

- [ ] `AC-OP-01` [공통] Opportunity는 다음 정보를 가진다: 이름(필수), 소속 Account(필수), 주 담당자 Contact(선택, 그 Account 소속이어야 함), 금액(필수, 0 이상 정수, 통화 TBD-10), 예상 마감일(필수), 단계(필수, TBD-3), 메모, 생성 시각, 종료 시각(수주·실패로 바뀐 시각, 열린 건은 비어 있음).
- [ ] `AC-OP-02` [공통] Opportunity를 직접 생성·수정할 수 있다. 생성 시 단계는 첫 번째 열린 단계로 고정되며, 다른 단계로 생성할 수 없다. (예시 데이터 적재는 예외. 적재된 Opportunity도 이력은 `AC-OP-11` 규칙대로 남긴다)
- [ ] `AC-OP-03` [BE] 금액이 음수이거나 정수가 아니거나, 예상 마감일이 날짜가 아니면 거부된다. 과거 날짜는 허용한다 (예시 데이터·지연 건 표현을 위해).
- [ ] `AC-OP-04` [BE] 주 담당자 Contact가 소속 Account의 Contact가 아니면 생성·수정이 거부된다. (03의 `AC-CT-04`로 사후에 달라지는 경우는 허용)
- [ ] `AC-OP-05` [공통] 열린 Opportunity는 삭제할 수 있다. 종료된(수주·실패) Opportunity는 삭제할 수 없다. 삭제하면 단계 이력도 함께 사라진다.
- [ ] `AC-OP-06` [FE] Opportunity 상세는 기본 정보, 단계 변경 UI, 단계 이력(최신순), 활동 목록(TBD-8)을 보여 준다.

### 3.2 단계 상태 머신

- [ ] `AC-OP-07` [BE] 단계 목록과 순서, 열린 단계·종료 단계 구분, 허용 전이 표는 TBD-3 확정값을 따른다. 허용 전이 표는 **서버가 단일 기준**이며 FE는 서버가 알려 주는 "현재 단계에서 갈 수 있는 단계" 정보로 버튼을 그린다. (FE가 규칙을 복제하지 않는다)
- [ ] `AC-OP-08` [BE] 허용되지 않은 전이(예: 단계 건너뛰기, 종료 단계에서 열린 단계로 복귀)를 요청하면 거부되고, 거부 사유에 현재 단계·요청 단계·허용되는 단계 목록이 포함된다. Opportunity는 변하지 않고 이력도 추가되지 않는다.
- [ ] `AC-OP-09` [BE] 종료 단계(수주·실패)에 들어가면 종료 시각이 기록되고, 이후 단계 변경·수정·삭제가 모두 거부된다. (메모 수정 허용 여부는 API 계약에서 결정. 기본은 전체 잠금)
- [ ] `AC-OP-10` [BE] 같은 Opportunity에 대해 단계 변경 요청이 동시에 두 번 들어오면(두 탭, 연속 클릭) 하나만 적용되고 다른 하나는 "이미 변경됨"으로 거부되거나 같은 결과로 수렴한다. 이력이 중복·교차로 남지 않는다. **검증 방법**: 같은 Opportunity에 "협상 → 수주"와 "협상 → 실패"를 동시에 보냈을 때 종료 단계가 둘 중 하나로만 확정되고 이력이 정확히 1건 추가된다. (동시성 제어 방식은 사용자 결정, ADR·트러블슈팅 후보)
- [ ] `AC-OP-11` [BE] 단계 이력은 다음을 가진다: 이전 단계(생성 시에는 비어 있음), 새 단계, 변경 시각, 변경 사유(선택, 실패 시 권장). Opportunity 생성(직접·전환·예시 적재 모두)에 1건, 이후 모든 단계 변경마다 1건이 **단계 변경과 함께** 남는다. 단계는 바뀌었는데 이력이 없거나, 이력은 있는데 단계가 안 바뀐 상태가 생기지 않는다.
- [ ] `AC-OP-12` [BE] 단계 이력은 수정·삭제 API가 없다 (Opportunity 삭제 시 함께 삭제되는 것만 허용).
- [ ] `AC-OP-13` [FE] 단계 이력은 타임라인 형태로 보여 주고, 각 구간에 머문 기간(예: "제안 단계 5일")을 계산해 표시한다. 계산은 FE에서 해도 된다.
- [ ] `AC-OP-14` [FE] 실패 단계로 옮길 때 사유를 입력하는 입력란을 제공한다 (선택).

### 3.3 파이프라인 칸반

- [ ] `AC-OP-15` [FE] 파이프라인 화면은 **열린 단계**를 열(column)로 두고 각 열에 해당 단계의 Opportunity 카드를 보여 준다. 카드에는 이름, Account명, 금액, 예상 마감일이 있다. 각 열 머리에 건수와 금액 합계를 보여 준다.
- [ ] `AC-OP-16` [FE] 종료된 건(수주·실패)은 칸반 열에 섞지 않고, 별도 영역이나 토글로 본다.
- [ ] `AC-OP-17` [FE] 카드를 다른 열로 끌어다 놓거나(드래그) 카드 메뉴로 단계를 바꿀 수 있다. 둘 중 드래그는 선택 사항이고 메뉴 방식은 필수다. 허용되지 않는 전이는 열이 비활성 표시되거나 놓는 순간 서버 거부 사유가 안내된다.
- [ ] `AC-OP-18` [FE] 단계 변경이 거부되면 카드는 원래 열로 돌아가고 `AC-OP-08`의 사유가 보인다.
- [ ] `AC-OP-19` [FE] 예상 마감일이 지난 열린 건은 카드에 "지연" 표시가 있다.
- [ ] `AC-OP-20` [FE] 칸반에서 Opportunity 생성 진입점(기존 Account 선택 → 생성)이 있다.
- [ ] `AC-OP-21` [BE] 파이프라인 조회는 열린 Opportunity를 단계별로 묶어 돌려주고, 각 단계의 건수·금액 합계를 포함한다 (06 대시보드와 같은 집계 규칙을 쓴다. `AC-DB-02` 참조).

### 3.4 공통

- [ ] `AC-OP-22` [BE] `AC-COMMON-01~05`를 만족한다. 특히 다른 작업 공간의 Opportunity에 단계 변경을 요청하면 "존재하지 않음"으로 거부된다 (`AC-WS-26`).
- [ ] `AC-OP-23` [BE] 작업 공간당 Opportunity 200건(`01-trial-workspace.md` `AC-WS-37`)을 넘는 생성은 거부된다.

## 4. 제외 범위

- 단계별 확률(가중 파이프라인), 예상 수익 계산
- 단계 정의를 작업 공간마다 바꾸기 (단계는 전역 고정)
- 종료된 건 재오픈
- Opportunity 제품 라인(품목·수량), 견적
- 담당자 배정, 팀 파이프라인
- 칸반 열 커스터마이징, 저장된 필터
- 이력 되돌리기
