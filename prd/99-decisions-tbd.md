## TBD-3. Opportunity 단계 정의와 허용 전이 (최우선)

다른 TBD(수주율, Lead 전환 첫 단계)와 예시 데이터의 단계별 분포(01 §3.4.1)가 이 결정에 의존하므로 먼저 적는다.

### 후보 A. 4단계 + 종료 2개 (HANDOFF 예시 그대로)

`발굴 → 제안 → 협상 → (수주 | 실패)`

- 장점: HANDOFF와 일치. 단계가 적어 칸반이 한 화면에 들어가고 예시 데이터 분포가 단순하다.
- 단점: "발굴"과 "제안" 사이가 멀어 체험 시 단계 이동이 금방 끝난다.

### 후보 B. 5단계 + 종료 2개

`발굴 → 검증 → 제안 → 협상 → (수주 | 실패)`

- 장점: Lead의 "검증"과 Opportunity의 "검증" 단계가 이어져 흐름이 자연스럽다. 상태 머신 전이 표가 더 풍부해 설명 포인트가 두드러진다.
- 단점: Lead 검증과 이름이 겹쳐 혼동 가능. 모바일 폭에서 열 5개는 좁다.

### 허용 전이 규칙 (단계 수와 별개로 결정)

| 규칙안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| R1. 엄격 | 앞으로 한 단계씩만. 뒤로 못 감. 실패는 어느 열린 단계에서나 가능. 수주는 마지막 열린 단계(협상)에서만 | 상태 머신이 분명해 거부 케이스가 많고 테스트·설명이 쉽다 | 실수로 옮긴 카드를 되돌릴 수 없어 체험 중 답답할 수 있음 |
| R2. 한 칸 후진 허용 | R1 + 바로 이전 열린 단계로 한 칸 후진 허용 | 실수 복구 가능하면서도 "건너뛰기 금지"라는 규칙은 유지 | 후진 이력이 쌓여 "머문 기간" 계산이 복잡해짐 |
| R3. 열린 단계 간 자유 | 열린 단계끼리는 자유 이동. 종료는 어디서나 가능하고 종료 후 잠금 | 사용성 최고 | 상태 머신이 "종료 잠금"뿐이라 설명 포인트가 약함 |

### PM 추천

**후보 A + R2**. 이유: HANDOFF 예시를 그대로 쓰고, "건너뛰기 금지·종료에서 복귀 금지·수주는 협상에서만"으로 거부 케이스가 충분하면서 한 칸 후진으로 체험 중 실수를 복구할 수 있다. 전이 표 초안:

| 현재 \ 이동 | 발굴 | 제안 | 협상 | 수주 | 실패 |
|---|---|---|---|---|---|
| 발굴 | - | O | X | X | O |
| 제안 | O | - | O | X | O |
| 협상 | X | O | - | O | O |
| 수주 | X | X | X | - | X |
| 실패 | X | X | X | X | - |

## TBD-4. 수주율 계산 기준

| 후보 | 식 | 장점 | 단점 |
|---|---|---|---|
| **A. 건수, 종료 건 기준** | 수주 건수 ÷ (수주 + 실패 건수) | 가장 흔한 정의. 열린 건이 분모에 안 들어가 진행 중 변동이 없음 | 종료 건이 적으면 비율이 크게 흔들림 (예시 데이터 4건이면 75%) |
| B. 건수, 전체 기준 | 수주 건수 ÷ 전체 Opportunity 수 | 파이프라인 전체 대비 성과 | 열린 건이 많을수록 낮아져 "수주율"이라는 이름과 안 맞음 |
| C. 금액, 종료 건 기준 | 수주 금액 ÷ (수주 + 실패 금액) | 큰 건 수주를 반영 | 고액 건 하나로 왜곡. 설명이 길어짐 |

### PM 추천

**A**. 대시보드에 "종료 건 기준 · 건수" 라벨을 붙인다(`AC-DB-10`). 금액 기준(C)을 같이 보여 주고 싶으면 `AC-DB-01`에 "수주 금액 / 실패 금액"이 이미 있으므로 FE에서 보조 수치로 추가할 수 있다 (범위 제안 2 참고).

## TBD-16. 제외 해제 후 Lead 상태

02 §3.2 전이 표의 "제외" 행. "제외"는 전환됨이 아닌 상태에서 언제든 지정하고 풀 수 있다고 정해졌으나, 풀었을 때 어느 상태로 돌아가는지는 정해지지 않았다.

| 후보 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A. 제외 전 상태로 복귀 | 제외할 때 직전 상태를 기억했다가 해제 시 그 상태로 돌린다 | 실수로 제외한 Lead를 그대로 복구할 수 있어 자연스러움 | "직전 상태"를 저장해야 하고, 전이 표가 저장된 값에 따라 달라져 규칙 설명이 길어짐 |
| B. 항상 "신규"로 | 제외 해제 = 신규 | 단순. 전이 표가 고정 | 검증됨이었던 Lead도 다시 진행 중·검증됨을 거쳐야 함 |
| **C. 해제 시 상태를 고른다** | 제외 → 신규·진행 중·검증됨 중 하나로 직접 변경 (별도 "해제" 동작 없음) | 저장 필드 없음. 상태 변경 UI 하나로 끝나 FE·BE 모두 가장 단순. 전이 표의 제외 행이 O·O·O로 고정 | Lead 상태 머신이 "전환됨만 잠금"에 가까워져 규칙이 적어짐 (Opportunity 상태 머신이 주 설명 포인트이므로 큰 손실은 아님) |

### PM 추천

**C**. Lead 상태 머신에서 설명 가치가 있는 규칙은 "전환됨은 전환으로만 진입·최종"(`AC-LD-08`)과 "전환은 검증됨에서만"(`AC-LD-09`) 두 가지이고, 제외 해제는 거기에 보태는 것이 없다. 상태 변경 UI(`AC-LD-06`)도 선택지 하나로 끝난다.
