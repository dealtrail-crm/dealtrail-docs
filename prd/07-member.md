## 1. 목적

테스트 계정은 24시간 제한이라 며칠에 걸쳐 써 보기 어렵다. 회원 계정은 **아이디와 비밀번호만으로** 가입해 만료 없이 같은 작업 공간을 이어서 쓰게 한다. 개인정보를 받지 않으므로 데이터는 기간 없이 보관하고, 비밀번호 복구 같은 기능도 두지 않는다. 가입 뒤의 흐름(업종 선택 → 예시 데이터 → 초기화)과 격리·상한 규칙은 01과 같으며, 이 문서는 회원에만 해당하는 것만 적는다.

## 2. 유저 스토리

- US-MB-1. 방문자로서, 며칠에 걸쳐 써 보고 싶을 때 아이디·비밀번호만으로 가입하고 싶다. 24시간 제한 없이 이어서 보기 위해.
- US-MB-2. 회원으로서, 가입 직후에도 테스트 계정처럼 예시 데이터가 들어 있는 CRM으로 시작하고 싶다. 빈 화면에서 시작하지 않기 위해.
- US-MB-3. 운영자(사용자 본인)로서, 자동화된 가입으로 데이터가 무한히 늘지 않길 원한다. 비용을 통제하기 위해.

## 3. 인수조건

용어는 `00-overview.md` 4장을 따른다. 세션·비밀번호·로그아웃 규칙은 `AC-COMMON-09`~`14`.

### 3.1 가입

- [ ] `AC-MB-01` [공통] 아이디와 비밀번호만으로 가입한다. 이메일·이름 등 개인정보는 받지 않는다. 소셜 로그인은 없다. 아이디는 영문 소문자·숫자·`_`로 4~20자이고, 비밀번호 규칙은 `AC-COMMON-10`을 따른다. 규칙에 맞지 않으면 `AC-COMMON-05` 형식으로 거부되고 FE는 입력란 옆에 규칙을 보여 준다.
- [ ] `AC-MB-02` [BE] 아이디는 전체에서 유일하다. 이미 있는 아이디나 테스트 계정의 아이디로 가입하려 하면 `AC-COMMON-05` 형식으로 거부된다.

### 3.2 로그인

- [ ] `AC-MB-03` [공통] 회원은 아이디·비밀번호로 로그인·로그아웃한다 (`AC-COMMON-12`~`14`). 회원 세션의 유지 기간 상한은 API 계약에서 정한다. 비밀번호 찾기·변경은 없다 (복구에 쓸 개인정보가 없다). FE는 가입 화면에서 이 사실을 안내한다.

### 3.3 보관

- [ ] `AC-MB-04` [공통] 회원 계정과 그 작업 공간은 만료 시각이 없고 남은 시간 표시도 없다. 기간 없이 **영구 보관**하며 자동 삭제가 없다. 01의 정리 작업(`AC-WS-32`, `AC-WS-33`)의 대상이 아니다.

### 3.4 작업 공간

- [ ] `AC-MB-05` [공통] 회원은 가입 직후 테스트 계정과 같은 흐름을 탄다. 01의 다음 인수조건이 회원에게 그대로 적용된다: 업종 선택과 작업 공간 생성 `AC-WS-12`~`17`, 예시 데이터 `AC-WS-18`~`22`, 초기화 `AC-WS-23`~`25`, 격리 `AC-WS-26`·`27`, 엔티티 상한 `AC-WS-37`·`38`. 초기화 뒤에도 회원 계정은 그대로이며 새 업종을 골라 다시 시작한다.

### 3.5 가입 남용 방지

값은 모두 코드 변경 없이 바꿀 수 있는 설정값이다.

- [ ] `AC-MB-06` [BE] 같은 IP에서 하루(24시간 이동 창)에 **3건**을 넘는 가입은 거부된다. 거부 사유는 FE에 전달된다. (IP 식별 방법은 `AC-WS-06`과 같다)
- [ ] `AC-MB-07` [BE] 전체 회원 수가 **500명**에 이르면 새 가입은 거부되고, FE는 "가입이 잠시 닫혔다"는 안내를 보여 준다. 발생할 때마다 발생 시각이 로그로 남는다 (`AC-WS-08`과 같은 목적). `AC-MB-06`의 거부와 사유가 구분된다.

### 3.6 진입점

- [ ] `AC-MB-08` [FE] 첫 화면과 "체험 계정이 모두 사용 중" 화면(`AC-WS-07`)에 회원가입·로그인 진입점이 있다. 체험하기(테스트 계정)보다 눈에 덜 띄게 둔다 (핵심 원칙은 즉시 체험이다).

## 4. 제외 범위

- 소셜 로그인, 이메일 인증, 비밀번호 찾기·변경, 아이디 변경
- 회원 탈퇴(즉시 삭제), 프로필·설정 화면
- 계정 하나에 작업 공간 여러 개, 작업 공간 공유
- 휴면 회원 정리, 보관 기간 제한
- 캡차 등 가입 시 추가 확인 (개인정보 없는 가입 원칙과 어긋난다)

## 5. 의존성 / 열린 질문

- 01의 업종 선택·작업 공간·초기화·격리·상한이 구현되어야 회원 흐름이 성립한다. 회원 고유 작업은 가입·로그인·남용 방지·진입점이다.
- 회원 세션 유지 기간 상한, 세션 보관 수단은 API 계약에서 정한다.
- Epic 분리와 우선순위(`priority:medium`)는 사용자 확정 대상이다.
