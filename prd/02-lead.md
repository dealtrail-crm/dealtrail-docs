# 02. Lead 등록·검증·전환

## 1. 목적

Lead는 "아직 검증되지 않은 잠재 고객"이다. 영업 담당자는 Lead를 등록하고, 가치가 있다고 판단하면 검증하고, 검증된 Lead를 **전환**해 Account·Contact·Opportunity를 한 번에 만든다. 전환은 이 제품에서 가장 중요한 쓰기 작업이며, 세 엔티티가 모두 만들어지거나 하나도 만들어지지 않아야 한다.

## 2. 유저 스토리

- US-LD-1. 영업 담당자로서, 새 잠재 고객을 회사명·담당자명·연락처 정도만으로 빠르게 등록하고 싶다. 정식 거래처로 만들기 전에 가볍게 쌓아 두기 위해.
- US-LD-2. 영업 담당자로서, Lead 목록에서 상태별로 어떤 Lead가 있는지 보고 싶다. 다음에 연락할 대상을 고르기 위해.
- US-LD-3. 영업 담당자로서, 연락 중인 Lead를 "진행 중"으로, 가치가 확인된 Lead를 "검증됨"으로 표시하거나 가망 없음으로 제외하고 싶다. 전환할 가치가 있는 것만 남기기 위해.
- US-LD-4. 영업 담당자로서, 검증된 Lead를 한 번의 동작으로 Account·Contact·Opportunity로 전환하고 싶다. 같은 정보를 세 번 입력하지 않기 위해.
- US-LD-5. 영업 담당자로서, 전환이 실패했을 때 반쯤 만들어진 데이터가 남지 않길 원한다. 중복된 Account나 주인 없는 Contact를 정리하는 일이 없도록.
- US-LD-6. 영업 담당자로서, 전환된 Lead에서 어떤 Account·Opportunity가 만들어졌는지 따라가고 싶다. 이력을 추적하기 위해.

## 3. 인수조건

### 3.1 등록·조회·수정

- [ ] `AC-LD-01` [공통] Lead는 다음 정보를 가진다: 회사명(필수), 담당자명(필수), 이메일, 전화번호, 직함, 유입 경로(선택, 자유 입력 또는 짧은 선택지), 메모, 상태(신규 / 진행 중 / 검증됨 / 전환됨 / 제외, 3.2 참조), 생성 시각. 필드 세부(길이·형식)는 API 계약에서 확정한다.
- [ ] `AC-LD-02` [FE] Lead 목록 화면에서 상태별 필터와 회사명·담당자명 검색이 된다. 기본 정렬은 최근 생성 순.
- [ ] `AC-LD-03` [FE] Lead 등록 폼은 필수 두 항목만 채우면 저장된다. 나머지는 비워 둘 수 있다.
- [ ] `AC-LD-04` [BE] 필수값이 비거나 이메일 형식이 틀리면 `AC-COMMON-05` 형식으로 거부된다.
- [ ] `AC-LD-05` [공통] 전환되지 않은 Lead는 수정·삭제할 수 있다. 전환된 Lead는 수정·삭제할 수 없고, 시도하면 "전환된 Lead"임을 이유로 거부된다.
- [ ] `AC-LD-06` [FE] Lead 상세 화면에서 상태 변경(신규·진행 중·검증됨·제외, 3.2의 전이 표를 따름)과 전환 버튼을 제공한다. 전환 버튼은 "검증됨" 상태에서만 활성화된다. 전환된 Lead에서는 상태 변경과 전환 버튼을 모두 제공하지 않는다.

### 3.2 상태(검증)

Lead 상태는 다섯 가지다. 신규·진행 중·검증됨은 "열린 상태", 제외는 "보류 상태", 전환됨은 "최종 상태"다.

| 현재 \ 변경 | 신규 | 진행 중 | 검증됨 | 제외 | 전환됨 |
|---|---|---|---|---|---|
| 신규 | - | O | O | O | X |
| 진행 중 | O | - | O | O | X |
| 검증됨 | O | O | - | O | 전환 동작으로만 |
| 제외 | TBD-16 | TBD-16 | TBD-16 | - | X |
| 전환됨 | X | X | X | X | - |

- [ ] `AC-LD-07` [BE] Lead 상태는 신규, 진행 중, 검증됨, 전환됨, 제외 다섯 값만 가진다. 등록 직후 상태는 "신규"다. 상태 변경은 위 전이 표를 따른다: 신규·진행 중·검증됨 사이는 어느 방향으로든 바꿀 수 있고, 전환됨이 아닌 상태에서는 언제든 "제외"로 바꿀 수 있으며, 제외를 풀 수도 있다(풀었을 때 돌아가는 상태는 TBD-16). 정의되지 않은 값이나 표에서 허용되지 않는 전이는 거부된다.
- [ ] `AC-LD-08` [BE] "전환됨"은 전환 동작을 통해서만 들어갈 수 있는 최종 상태다. 상태 수정으로 직접 "전환됨"을 지정할 수 없고, 전환됨에서 다른 상태로 바꾸려는 요청은 거부된다(`AC-LD-05`와 같은 이유).
- [ ] `AC-LD-09` [BE] 전환은 "검증됨" 상태에서만 허용된다. 신규·진행 중·제외 상태의 Lead를 전환하려 하면 거부되고, 아무 엔티티도 만들어지지 않는다.

### 3.3 전환 (핵심)

- [ ] `AC-LD-10` [FE] 전환 화면은 Lead 정보로 미리 채운 세 영역을 보여 준다: Account(회사명), Contact(담당자명·이메일·전화·직함), Opportunity(이름 기본값 "회사명 - 건", 금액, 예상 마감일). 방문자는 값을 고쳐서 전환할 수 있다. 기존 Account를 고르는 입력은 없으며, 전환은 항상 새 Account를 만든다.
- [ ] `AC-LD-11` [BE] 전환 요청 한 번으로 Account, Contact, Opportunity(단계 이력 1건 포함, `AC-LD-14`)가 **모두 생성**되고 Lead 상태가 "전환됨"으로 바뀐다. 이 변경들은 함께 성공하거나 함께 실패한다.
- [ ] `AC-LD-12` [BE] 전환 도중 어느 단계에서 실패해도 Account·Contact가 남지 않고 Lead 상태도 바뀌지 않는다. **검증 조건**: Account·Contact가 저장된 뒤 Opportunity 저장 또는 Lead 상태 변경 단계에서 실패가 발생했을 때, 요청 전과 비교해 Account·Contact 수가 같고 Opportunity가 생기지 않았으며 Lead 상태가 그대로여야 한다. 실패를 일으키는 방법은 구현 시 사용자가 정한다. 요청 입력 검증 실패(`AC-LD-04` 형식)는 아무것도 저장하기 전에 거부되므로 이 검증의 대상이 아니다. (이 검증은 자동 테스트로 남겨 포트폴리오에서 보여 준다)
- [ ] `AC-LD-13` [BE] 생성된 Contact는 생성된 Account에 속하고, 생성된 Opportunity는 그 Account와 Contact에 연결된다.
- [ ] `AC-LD-14` [BE] 전환으로 생성된 Opportunity의 단계는 첫 번째 열린 단계(TBD-3)이고, 단계 이력에 "생성(전환)" 기록이 1건 남는다. (`04-opportunity-pipeline.md` `AC-OP-11` 참조)
- [ ] `AC-LD-15` [BE] 전환된 Lead는 자신이 만든 Account·Contact·Opportunity의 식별자를 기억한다. FE는 Lead 상세에서 그 세 개로 이동하는 링크를 보여 준다.
- [ ] `AC-LD-16` [BE] 같은 Lead를 두 번 전환하려 하면(연속 클릭, 두 탭 등) 두 번째는 "이미 전환됨"으로 거부되고 Account·Contact·Opportunity가 **중복 생성되지 않는다**. (동시성 처리 방식은 사용자 결정, 트러블슈팅 후보)
- [ ] `AC-LD-17` [FE] 전환 성공 후 생성된 Opportunity 상세 화면으로 이동하고, 성공 알림에 "Account·Contact·Opportunity가 만들어졌다"는 내용이 포함된다.
- [ ] `AC-LD-18` [FE] 전환 실패 시 어떤 입력이 문제였는지 전환 화면의 해당 영역에 표시되고, 입력값은 유지된다.

## 4. 제외 범위

- Lead 중복 감지·병합
- 전환 시 기존 Account 연결. 전환은 항상 새 Account를 만들므로 같은 회사의 Lead를 두 번 전환하면 Account가 중복 생성된다. Account 중복 감지·병합도 제외한다 (`03-account-contact.md` `AC-ACC-07`)
- Lead 담당자 배정, 담당자별 뷰 (사용자 개념 없음)
- Lead 점수(Scoring), 자동 검증 규칙
- 웹 폼·이메일로 Lead 자동 유입
- 전환 시 Opportunity 생성을 건너뛰는 옵션 (HANDOFF: 세 엔티티 동시 생성이 범위. "선택 생성"은 범위 제안으로만 둔다)
- 전환 취소(되돌리기)
